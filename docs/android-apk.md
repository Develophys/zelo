# Android APK (Capacitor)

Zelo ships from one codebase to two surfaces:

- **Browser** — the PWA at <https://zelo-dusky.vercel.app>, installable from Chrome/Safari via "Add to Home screen".
- **APK** — the same web build wrapped in a native Android shell by [Capacitor](https://capacitorjs.com), installable as a file.

The APK **bundles the web assets at build time**. It is not a browser pointed at the live site: a change to `apps/web` reaches the installed app only after you rebuild and reinstall. The browser build is unaffected by anything here.

## Prerequisites

Android Studio supplies both the JDK and the SDK; nothing else needs installing.

| Tool | Path |
| --- | --- |
| JDK 21 (Android Studio's bundled JBR) | `C:\Program Files\Android\Android Studio\jbr` |
| Android SDK | `C:\Users\<you>\AppData\Local\Android\Sdk` |
| `adb` | `<SDK>\platform-tools\adb.exe` |

Requires build-tools **36+**. Gradle downloads its own distribution (~150 MB) on the first build, and the Android Gradle Plugin fetches the `compileSdk` platform (currently `android-36`) automatically if it is missing, provided the SDK licence has already been accepted in Android Studio.

`apps/web/android/local.properties` points Gradle at the SDK. It is gitignored, so **each machine writes its own**:

```properties
sdk.dir=C:/Users/<you>/AppData/Local/Android/Sdk
```

Use forward slashes. See [Gotchas](#gotchas).

## One-time API configuration (required)

The installed app serves from origin `https://localhost`, which the API must allow. Without this the app loads normally and then **every request fails silently** — CORS blocks the responses before the app sees them, so it looks like an app bug rather than a config gap.

```bash
fly secrets set CORS_ALLOWED_ORIGINS="https://zelo-dusky.vercel.app,https://localhost" --app zelo-api
```

- The value is a full **replacement**, not an append — include every origin you still need. Fly secrets are write-only, so the current value cannot be read back.
- Triggers a rolling restart. Verify with `fly status --app zelo-api` and `curl https://zelo-api.fly.dev/health`.
- One variable covers both HTTP (`main.ts`) and WebSockets (`peer-chat.gateway.ts`).

## Build the APK

**1. Build the web assets and sync them into the native project:**

```bash
pnpm --filter @zelo/web android:sync
```

**2. Build the APK.** Run Gradle **from inside `apps/web/android`** — see [Gotchas](#gotchas).

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
Set-Location apps\web\android
.\gradlew.bat assembleDebug
```

```bash
# macOS / Linux
export JAVA_HOME=/path/to/jdk21
cd apps/web/android && ./gradlew assembleDebug
```

Output — roughly 10 MB, debug-signed:

```text
apps/web/android/app/build/outputs/apk/debug/app-debug.apk
```

## Install on a device

Over USB, with USB debugging enabled on the phone:

```bash
adb install apps/web/android/app/build/outputs/apk/debug/app-debug.apk
adb install -r <path>    # -r to replace an existing install
```

Or copy the APK to the phone and tap it. Because it is debug-signed, Android asks you to allow installs from unknown sources.

To rebuild after changing anything in `apps/web`, repeat both build steps and reinstall with `-r`.

## How the native build differs from the browser build

The `android:sync` script runs `build:native`, which differs from the normal `build` in two ways:

| Aspect | Browser (`build`) | Native (`build:native`) |
| --- | --- | --- |
| Service worker + manifest | generated by `vite-plugin-pwa` | **disabled** via `VITE_DISABLE_PWA=true` |
| `VITE_API_BASE_URL` | injected by the host (Vercel env) | hardcoded to `https://zelo-api.fly.dev` in the script |
| Origin at runtime | `https://zelo-dusky.vercel.app` | `https://localhost` |

Why each:

- **Service worker disabled.** Its assets are already local inside the APK, so caching them adds no offline benefit and introduces stale-content bugs.
- **API URL baked in.** There is no server to inject env vars. To target a different API, change `build:native` in [`apps/web/package.json`](../apps/web/package.json) and rebuild. A phone cannot reach your machine's `localhost`, so a LAN address (`http://192.168.x.x`) would need an Android cleartext-traffic exception — HTTPS avoids that entirely.
- **`https://localhost` on both platforms.** Capacitor defaults to `https://localhost` on Android but `capacitor://localhost` on iOS. [`capacitor.config.ts`](../apps/web/capacitor.config.ts) pins both to `https`, so a single CORS entry covers Android and a future iOS build. **Do not change this after release** — the scheme is part of the origin, and changing it wipes WebView storage, logging every user out because session tokens live in `localStorage`.

Launcher icons and splash screens are generated from the sources in `apps/web/assets/` by [`@capacitor/assets`](https://github.com/ionic-team/capacitor-assets):

```bash
pnpm --filter @zelo/web exec capacitor-assets generate --android
```

Re-run only when `apps/web/assets/*.png` change. `icon-foreground.png` keeps the mark inside the Android adaptive-icon safe zone (the inner ~61%), so it survives being masked into a circle, squircle, or rounded square.

## Publishing a release build

> Not yet exercised for this project. The Gradle commands are standard Capacitor; the Play Console steps assume a developer account that does not exist yet.

**1. Set the version** in [`apps/web/android/app/build.gradle`](../apps/web/android/app/build.gradle). `versionCode` must increase on every upload; `versionName` is the human-facing string.

```gradle
versionCode 2
versionName "1.1"
```

**2. Create a signing keystore.** Losing it means you can never update the app under the same package id again — back it up somewhere durable and private.

```bash
"C:\Program Files\Android\Android Studio\jbr\bin\keytool" -genkeypair -v \
  -keystore zelo-release.keystore -alias zelo -keyalg RSA -keysize 2048 -validity 10000
```

Keep the keystore **out of the repo**. Store the credentials in `apps/web/android/key.properties` — that filename, along with `*.keystore` and `*.jks`, is already gitignored:

```properties
storeFile=C:/absolute/path/to/zelo-release.keystore
storePassword=<store password>
keyAlias=zelo
keyPassword=<key password>
```

**3. Wire the signing config** into `apps/web/android/app/build.gradle`. The generated `release` block has no `signingConfig`, so `assembleRelease` currently produces an **unsigned** APK that no device will install.

```gradle
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('key.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

android {
    signingConfigs {
        release {
            storeFile file(keystoreProperties['storeFile'])
            storePassword keystoreProperties['storePassword']
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
        }
    }
    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled false
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
    }
}
```

**4. Build the artifact** for your distribution channel:

```bash
./gradlew assembleRelease    # APK  — direct download, sideloading, internal distribution
./gradlew bundleRelease      # AAB  — required by Google Play
```

```text
app/build/outputs/apk/release/app-release.apk
app/build/outputs/bundle/release/app-release.aab
```

**5. Distribute.**

- **Direct** — host the signed APK and let people download it. No account, no review; installers must permit unknown sources.
- **Google Play** — one-time $25 developer registration, then create the app in Play Console and upload the AAB. Use an internal testing track first; production submissions are reviewed. Play re-signs with its own key under Play App Signing, so your keystore becomes the *upload* key — still irreplaceable. `applicationId` (`com.develophys.zelo`) is **permanent** once published and cannot be renamed.

Play also enforces a minimum `targetSdk` that rises yearly; the project currently targets 36 (`apps/web/android/variables.gradle`).

## Repository changes

| Path | Purpose |
| --- | --- |
| [`apps/web/capacitor.config.ts`](../apps/web/capacitor.config.ts) | App id, name, `webDir`, background colour, `https` scheme on both platforms |
| `apps/web/assets/` | Icon and splash **sources** (1024²/2732²), generated from `public/zelo_logo.png` on brand green `#2f6b5e` |
| `apps/web/android/` | Generated native project — committed, so builds are reproducible. `local.properties`, `build/`, and release signing credentials are gitignored |
| [`apps/web/package.json`](../apps/web/package.json) | Capacitor dependencies plus the `build:native` and `android:sync` scripts |
| [`apps/web/vite.config.ts`](../apps/web/vite.config.ts) | `VITE_DISABLE_PWA` gate on the PWA plugin |

The Gradle step is deliberately **not** an npm script: `gradlew.bat` and `./gradlew` differ per OS, and hardcoding either would break the other once iOS/macOS work starts.

## Gotchas

**Run `gradlew` from `apps/web/android`, never with `-p <dir>`.** `capacitor.settings.gradle` locates the pnpm store through a relative path (`../../../node_modules/.pnpm/...`) resolved against the process working directory. With `-p` it resolves somewhere else and the build fails while resolving dependencies.

**`local.properties` needs forward slashes.** It is a Java `.properties` file, where `\` is an escape character — `C:\Users\...` silently collapses to `C:Users...` and Android Gradle Plugin fails with `java.io.IOException: Invalid file path` in `SdkLocator.validateSdkPath`. The message names no path, so it reads like a missing SDK rather than a malformed one.

**The APK and the website can be different versions.** The APK is built from your working tree; the website serves whatever was last deployed. When comparing the two, confirm both came from the same commit.

**Debug builds are for testing only.** They are signed with a throwaway debug key, cannot be upgraded in place to a release build, and cannot go to Play.

## Known open items

- **Safe-area insets are not consumed.** Android 15+ forces edge-to-edge, so web content extends behind the status and navigation bars. Capacitor's built-in `SystemBars` plugin defaults to `insetsHandling: "css"` and injects `--safe-area-inset-top/right/bottom/left` onto `documentElement`, but no CSS references them (nor `env(safe-area-inset-*)`). Fixing it means padding the app shell with `max(env(safe-area-inset-top, 0px), var(--safe-area-inset-top, 0px))` — the `env()` half also covers iOS, and both fall back to `0px` in desktop browsers. `BottomNav` happens to carry a hardcoded `pb-6` that approximates the gesture-bar height.
- **`public/icon-192.png` and `public/icon-512.png` are blank.** Both are solid `rgb(15,23,42)` with no logo, so browser PWA installs get an empty tile. The APK is unaffected — it uses `apps/web/assets/`. Regenerating the web icons from the same source would align both paths.

## iOS later

`capacitor.config.ts` and the web build are shared, so adding iOS is `pnpm --filter @zelo/web exec cap add ios`. The constraints are Apple's, not Capacitor's:

- Building an `.ipa` requires **macOS with Xcode**. There is no supported path on Windows.
- There is no sideloading equivalent to an APK. Distribution needs the Apple Developer Program ($99/year) for TestFlight or the App Store; free personal provisioning expires after 7 days and still needs a Mac.
- Safari's "Add to Home screen" already gives an installed-app experience on iOS with no tooling or account.
