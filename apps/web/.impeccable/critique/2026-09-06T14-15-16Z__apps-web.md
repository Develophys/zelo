## Fixed this round

1. ⬜→✅ **Desktop trend chart bars now encode the actual trend.** `toTrendBarHeights` (`manager-trend-chart.ts`) rescales desktop bar heights to the series' own min/max range instead of a fixed 0–100 axis, so a real 40%→46% rise is visually obvious instead of a 3px sliver. Mobile's literal-percentage width bars are untouched (they're read next to a printed number and are correct as absolute values).
2. ⬜→✅ **Failed invite notifications now offer a real recovery action.** `INVITE_EMAIL_FAILED` payloads now carry the account `id` (added across all four API call sites: `create-manager`, `create-peer-partner`, `send-manager-set-password-email`, `send-peer-partner-set-password-email`); the notification row shows a "Reenviar convite" button that calls the existing resend mutation and marks the notification read on success. Notifications that predate this field fall back gracefully (no button, no crash).
3. ⬜→✅ **Three void destinations now have real content.** `/peers` (unlinked) gets a 2-step "Como funciona" explainer using the app's existing numbered-badge pattern; the peer-partner inbox's idle state states what happens next ("Você recebe um alerta assim que alguém pedir para conversar").

6. ⬜→✅ **A new "thin border + wide shadow" detector finding on the chat action tray's collapse tab** (introduced by round 5's own fix for the tab reading as a glitch) was caught by this round's browser evidence and fixed before being reported as a finding — swapped `shadow-lift` for a plain fill-contrast (`bg-canvas-alt`) treatment.

## Investigated and found already correct — not fixed

- **The chat action tray's toggle uses `aria-pressed`, not `aria-expanded`.** Assessment A flagged this as a disclosure-semantics bug. It's a deliberate, tested decision (`ChatPage.test.tsx:1300`, "announces the tray tab as a density toggle rather than a disclosure") — both shortcuts stay in the accessible tree and clickable in both states; nothing is actually shown or hidden, so `aria-expanded` would misrepresent the interaction. Left unchanged.
- **Mobile manager nav shows a dot instead of an unread count.** `ManagerBottomNav.tsx` always passes `asDot`, while the sidebar only does so when collapsed. The accessible name always carries the real count either way (`ManagerUnreadBadge.tsx`'s own doc comment), and the existing numeric badge variant assumes a horizontal row layout that doesn't fit the bottom nav's vertical icon-over-label slot without a new positioned-badge treatment. Deferred rather than shipping a cramped fix.
